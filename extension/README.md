# Ogenkou

リポジトリ全体の構成と、CW／SによるVivliostyle Coreの利用方法は [ルートのREADME](../README.md) を参照してください。

## インストールと使い方

`artifacts/ogenkou-0.9.0.vsix` をVS Codeの「拡張機能: VSIXからのインストール」で選びます。開発時はF5の `Run Ogenkou` を実行します。このデバッグ起動では他のインストール済み拡張機能を無効にします。検証環境はWindows、VS Code 1.141.0、既存Chromeです。

`.novel`／`.nv` を開き、原稿エディタ右上の **Ogenkou: 原稿プレビューを開く** ボタンを押します。コマンドパレットからも実行できます。作品直下の原稿を自然順で結合し、未保存内容を反映します。初回は全文完成を待ち、その後通常本文はCW／Sで更新します。

初期組版中は上部の円形表示で進捗（原稿量に基づく推定％）を表示します。初期紙面の表示まで更新・PDF・設定適用・作品設定の固定化を無効にします。設定の下書き編集は可能です。進捗と状態表示の領域を確保し、更新中の表示でもボタン位置を維持します。紙面のスクロールバーは表示せず、ホイールはページ送り（見開きでは見開き単位）、Ctrl／Meta＋ホイールは倍率変更に使います。

上部で単ページ・見開き・自動、倍率・フィット、先頭末尾・前後・ページ番号を操作できます。下部はシークバー。倍率・リサイズは表示に作用し、用紙の組版条件を変更しません。Ctrl＋左ドラッグで紙面または背景をつかんで表示位置を移動できます。別ページへの移動で配置をリセットします。総数は最新の全文確定版の値です。紙面クリックは対応原稿へ移動します。削除された文字は編集境界へ補正し、履歴不足の場合は更新を案内します。

「連続するダッシュを連結する」は `―`／`—` が2文字以上続く部分を、文字幅と原稿位置を保った連続線で表示します。縦書き・横書きに対応し、offではフォント本来の字形を使います。


左の☰は見出し、右の☰は組版設定です。「この作品／デフォルト」を選び、変更後に適用します。未適用変更中は編集対象を切り替えられません。閉じてもdraftを保持し、「未適用の変更を破棄」で最新設定を読み直します。既存設定ファイルはGUI適用で自動保存しません。


設定は幅・高さ（mm）と用紙の向き、上下／ノド／小口の余白欄を用意しました。autoの計算値は無効な欄へ表示し、無効な版面は適用を拒否します。収まり・柱の侵入警告は常時表示します。カスタム余白では字数・行数を版面決定に使いません。上下の柱を分け、関連入力を横に並べ、一段では段間隔を隠します。柱の見出しは「柱の見出しの最大文字数」で調整できます（既定14、「…」を含む）。空欄なら省略しません。用紙別resetは現在の用紙・組方向のプリセットを使います。

**目次のon/offは右☰ → 作品情報 → 目次を生成する。** JSONCでは `overrides.processing.toc`。「目次に含める見出しの深さ」で1〜6を選べます（既定3、JSONCは `overrides.processing.tocDepth`）。offでも深さの設定と見出し一覧は残ります。ONではタイトルページの後（タイトルページがなければ作品先頭）へ自動挿入し、原稿の `[[toc]]` の位置は使いません。目次の先頭を左ページに固定し、必要に応じて空白ページを挟みます。用紙のB判は日本で一般的な寸法を使い、既存の `B5` 等のISO解釈は保持します。

作品CSSは `styles/custom.css` のひな形を作成し、設定の `style` に `"styles/custom.css"` を指定して使えます。既存ファイルを上書きしません。

上部の **PDF** または **Ogenkou: PDFを書き出す** で、同じ変換・資源収集経路から全文組版します。既存Chrome／Edge／Chromiumを検出し、`ogenkou.pdf.browserPath` で指定できます。ブラウザの同梱・自動取得はありません。既存PDFの上書き確認は保存ダイアログにまとめ、拡張機能から同じ確認を繰り返しません。処理はキャンセルできます。

VS Code設定では自動更新、カーソル移動追従、表示方法、空白を含む文字数、ユーザー正規表現ハイライトを設定できます。正規表現は別Workerで時間予算を設け、長い処理を中断します。文字数はルビの親文字を数え、小説記法を除去しますが一般Markdownの記号は含みます。Git HEADとの差分は現在原稿について表示します。


開発手順は [ルートのREADME](../README.md)、実装の構成は [DESIGN.md](../DESIGN.md) を参照してください。

## タイトルとタイトルページ

設定GUIは「作品情報」「紙面のレイアウト」「柱・ノンブルの設定」「組版処理」の4タブです。タイトル・著者・タイトルページ・目次は「作品情報」にまとめています。タブを切り替えても未適用の編集を保持し、最後に「適用」でまとめて反映します。

作品タイトル・著者は右☰ → この作品 → 作品情報で入力し、「適用」で `ogenkou.jsonc` の `publication.title` / `publication.author` へ反映します。既存設定ファイルの保存はVS Codeから行います。原稿には挿入しません。先頭の `.nv` / `.novel` の冒頭へVFMのFrontmatterで `title` / `author` を書くこともできます。作品設定の指定を優先します。

```markdown
---
title: 夜の物語
author: 筆者
---

# 第一章

本文。
```

右☰ → 作品情報 →「タイトルページを生成する」で切り替えます（JSONCでは `overrides.processing.titlePage`）。既定はONで、タイトルがある場合に限り、目次・本文の前へタイトルと著者を中央に置いた独立ページを追加します。タイトルページには柱・ノンブルを表示しません。通常の見出しを作品タイトルとして自動採用することはありません。

右☰ → 柱・ノンブルの設定 →「柱の見出しの最大文字数」は `overrides.layout.runningHeadMaxLength`（文字列）。`"14"` なら14文字以内に省略し、`""` なら省略しません。見出し本文・目次・見出し一覧は省略しません。

版面の収まりは「紙面のレイアウト」内で入力中に検証し、不正な組み合わせや柱との重なりの可能性を赤字で表示します。確認ボタンはありません。本文領域は紙面設定、柱との重なりには柱の文字サイズ・紙端からの距離も使います。

新規作品設定とCSSひな形はタブを開かずに作成・保存します。ルビ・傍点の専用構文ハイライトは行いません。記法の変換とユーザー定義の正規表現ハイライトは引き続き利用できます。連続ダッシュは元の文字と幅を維持して細い連続線で描きます（線幅0.03em、本文9ptなら0.27pt）。

## 作品設定を使い回す

標準機能の組版CSSは拡張機能が生成します。通常はFrontmatterも `custom.css` も書く必要はなく、`ogenkou.jsonc` を別作品にコピーすれば、用紙・余白・文字・段組み・柱・タイトルページ・目次の設定を引き継げます。タイトル・著者は作品情報から変更します。

目次の組方向は右☰ → 作品情報 → 目次で「本文に従う／横書き／縦書き」を選べます（`overrides.processing.tocWritingMode`）。目次の行送りは `overrides.processing.tocLineHeight`、既定は2倍です。縦書き目次のページ番号は本文とは別に縦中横を適用します。1・12・123・1234の4通りで一文字分の高さになることを検証しています。

原稿はVFMでHTMLへ変換し、文書全体のHTML・CSSをOgenkouが生成します。タイトル・著者は作品設定を優先し、Frontmatterを補助入力として利用します。目次の組方向・行送りはGUIと作品設定から指定できます。

文字サイズはptで指定します。空の原稿も白紙1ページとして表示し、入力後の全削除でも同じ状態へ戻ります。初期組版の進捗円グラフはページ数の隣に表示します。
