# 本家と現行Coreの速度比較

550試行の結果は [本家比較結果.md](本家比較結果.md)、各10試行の値と補助指標は [本家比較結果.json](本家比較結果.json) に保存した。

## 何を比較するか

以下の測定は、基本的な本文組版で「通常組版の高速化」「全文更新の再利用」「対象紙面までで止めるS」の総合効果を示す比較として適切です。本家と現行の差には複数の改修が含まれるため、個々の探索・CSS判定・再利用等の寄与を、この比較だけで分離することはできません。

| メニュー | 本家 | 現行Core |
| --- | --- | --- |
| (1) 初回全文組版 | 初回入力からloadedまで | 初回入力から全文完成のloadedまで |
| (2) 空行を1つ追加し全文完成 | 既存Viewerへ編集後の文書をロードし、全文loadedまで | 既存ViewerへrefreshMemoryDocumentを投入し、再利用を許可して全文loadedまで |
| (3) 同じ追加で変更紙面完成 | (2)の同じ実測値を参照 | 完成済みローカルseedの複製開始から、対象が解決されたfocusedterminalまで |

字数は5,000／10,000／20,000／40,000／80,000。各セル10試行。(2)(3)は前半・中盤・後半の3か所です。本家の(3)は別試行として重複計上せず、同じ字数・位置・trialの(2)を参照します。独立した時間測定は本家200件、現行350件、計550件です。

各字数・メニュー・位置に除外用のwarmupを1回追加します。Chromeは一つずつ逐次動かし、本家／現行CW／現行Sの実行順をtrialごとに交代します。中央値・最小・最大・平均・標準偏差と全10実測値を保存します。10件だけから精密なP95や速度保証は主張しません。

## 比較する版とビルド

本家は、このforkの起点となる公開版2.45.1、commit `13d0a9c4918cb91b97ff0253d2da5f0d2dc9de98` の未改変ソースです。現在の本家開発ブランチの最新版との比較ではありません。forkの旧masterには既にpreview改修が含まれているため、本家baselineには使用しません。

git archiveで本家のCoreソースを独立したディレクトリへ展開し、既存依存を使ってIIFEを生成します。現行と同じesbuild、minify、debug=false、ES2022 targetです。ソースの差を比較するためビルド条件をそろえており、本家の配布ファイル形式・ビルドtargetの違いは比較しません。本家ビルドに現行forkのソースが混入していないこともmetafileで検査します。

現在のCoreをビルドしてから測定してください。測定時のCore commit、未コミット変更、IIFEのSHA-256、ハーネスのhash、本家の版、実行環境、実行順とfixtureを結果ディレクトリへ保存します。

## 原稿と編集の定義

本文は自作の日本語散文で、生成本文のUTF-16文字数を指定字数ぴったりにします。120字ごとに段落を作り、段落番号を本文に含めてすべての段落を一意にします。同文反復のために段落の取り違えを紙面比較が見逃すことを避けます。縦書き、A6、9pt、行送り1.75、同一CSS・システムfontで組みます。画像・目次・柱・章の強制改ページは基本比較へ含めません。

前半／中盤／後半は、段落数の25％／50％／75％付近です。実際の挿入offsetも保存します。「先頭・末尾」や「章境界」の試験とは区別します。

挿入する空行は `<p><span id="edit-target"></span><br></p>` に相当する、紙面で一行の高さを持つ空段落です。単にHTMLに改行文字を足す操作ではありません。Sの対象は、その空段落のアンカーそのものです。

毎回、未編集の同じ原稿から全文完成済みのbaselineを作り、そこへ空行1つを追加します。前の試行で増えた空行を累積しません。baseline作成時間は更新の指標から除外します。

## 時計の境界

初回・全文更新はCore呼出しの直前からloaded受信まで、SはpreparePreviewSnapshotSeedの直前からfocusedterminal受信までを測ります。HTMLのDOM解析は両方とも計測に含めます。本家はDOMParserと公開loadDocument、現行は公開メモリ入力APIを使い、原稿のHTTP転送時間を除外します。Viewerの生成とJS bundleのロードは時計を開始する前に済ませます。

Sは別Viewerを使い、未編集のdonorを更新しません。ローカルseedの複製、編集後のHTML解析、CSS評価、再利用判定、組版を主指標へ含めます。新規S Viewerからの単発入力であり、既に暖まったSの連続使用だけを測った値ではありません。

次は別枠です。

- 可搬seedのexport、IPC、importによる受信・復元：主指標から除外。
- retainPreviewDisplayUnitAsyncによる表示用複製：S終了後に補助時間として保存。
- Markdown→HTML変換、資源収集、拡張Host、CW/S同時稼働、描画フレーム待ち：含めない。
- ブラウザ起動・font/cacheの完全cold状態：測らない。初回とは「そのViewerの初回組版」の意味。

現行のcomplete更新ではrenderAllPages=false、paginationMode=complete、reusePages=trueを使用します。明示的revisionにより全文完成を保証します。本家はrenderAllPages=trueで全文loadedを待ち、lazy表示のloadedを全文完成と誤認しません。

## 速度と併せて検査すること

時間は終端イベントで確定し、その後に紙面検査を行います。検査やsnapshot取得時間は主指標に入りません。

- 本家の全文結果に対して、現行の全紙面、またはSの対象紙面が一致すること。
- ページごとの本文、寸法、左右属性、TextNodeの表示矩形。位置は紙面内の相対座標で0.01pxへ丸める。
- 全文の本文に欠落がなく、空行アンカーが存在すること。Sでは対象解決とアンカーを含む紙面の成立を確認する。
- SのreusedPages、referenceCompletionRequired、対象ページ番号。seed複製時間・保持紙面複製時間も補助値で残す。

不一致やtimeoutは失敗として終了し、成功した時間だけで結果を完成扱いにしません。不一致は期待値・実際の紙面をJSONへ保存します。この検査はsourcemapの全契約や全文字のglyph画像一致を証明するものではありません。

## このメニューでカバーしないもの

1. **編集の種類**：長大な一段落内への文字挿入、改行位置の連鎖、削除、見出し変更、章追加、設定・CSS変更、複数箇所の変更。空行追加だけでは代表できない。空行がページ末尾の余白に吸収され、後続状態が早く一致する場合もあるため、今回の空行1つが常に後続全ページの再組版を強制するわけではない。
2. **CSS・資源の条件**：柱、目次のページ参照と目次一ページ増加、画像、font、表ヘッダ、脚注、float、段組、動的CSS、再利用できない条件からの全文fallback。通常組版の機能を省略していないことは別の機能検証で確認する。
3. **移送と表示の費用**：可搬seedの書出し・受信・復元、完成紙面packetの移送とCSS隔離、原稿位置対応の登録・保持、世代回収。今回の入力にはsourceMap sidecarを登録しない。Sは単ページ指定のため、見開きの隣ページまで組む費用と見開きseedの再利用もこの表だけでは示せない。S単体が速くても編集→紙面全体の時間が同じとは限らない。
4. **負荷と継続使用**：CW/Sの競合、連続編集、seedのrevision差、idle取込み、長時間メモリ、冷えたfont/cache、16万字以上。今回は10回の独立単発試行。
5. **改善の帰属**：現行Coreの再利用なし全文更新、索引・CSS判定等を個別に無効にした比較。この追加比較がなければ、初回以外の改善倍率を特定の改修だけの効果とは言えない。

従って、指定メニューを基本性能表として先に完成させ、既存の機能・IPC・連続入力検証へリンクする構成にします。すべての条件を巨大な一つの性能表へ増やすことはしません。

## 実行

リポジトリ直下で実行します。[測定用依存の準備](README.md#準備)と既存のChromeが必要です。

```console
npm run build --prefix vivliostyle/packages/core
node experiments/preview-benchmark/build-upstream-comparison.mjs
node experiments/preview-benchmark/run-upstream-comparison.mjs
```

測定完了後、試行数・集計値・bundleのhashを検査して共有用の結果表とJSONを生成します。

```console
node experiments/preview-benchmark/publish-upstream-comparison.mjs "結果ディレクトリ"
```

小規模の呼出し・紙面検証：

```console
node experiments/preview-benchmark/run-upstream-comparison.mjs --sizes=5000 --reps=1 --warmup=0
```

オプションは `--sizes`、`--reps`、`--warmup`、`--browser`、`--timeout`、`--output`、比較用build.jsonを指定する `--reference`。Windowsでカンマ区切りの引数を渡す場合は引用符で囲みます。

結果には `environment.json`、`results.json`、`summary.json`、`comparison.md`、Coreのbundleコピー、browser.mjs、字数・位置別fixtureを保存します。標準の出力先は `.recovery/upstream-comparison/<timestamp>/` です。
